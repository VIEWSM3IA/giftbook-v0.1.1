# 礼物簿 V0.2 交付契约

## 用户流程

先在私人礼物簿创建 TA 与礼物记录，再从该记录的「匿名分享」补充公开字段。表单展示公开预览；确认后经基础内容检查进入「看看」。已登录用户可按关系、年龄段、场景、价格区间、想要程度筛选，查看详情，并对别人的案例标记一次「有帮助」。作者在「我的分享」编辑补充字段或下架。

## 公开数据与隐私

`public_cases` 在发布时复制礼物名、关系、年龄段、场景、价格区间、想要程度、反应等级、行为证据和可选经验。公开 API 只返回这些字段、计数与当前用户的状态布尔值，不返回作者 ID、来源礼物 ID、TA 称呼、TA 备注、礼物私人备注或精确价格。修改 TA、礼物或价格不会自动改写已发布快照；删除私人礼物或 TA 会自动下架对应案例。主动下架不会删除私人礼物记录。注销账号会删除其案例与反馈。

关系、年龄、场景、价格区间、想要程度和反应由 `miniprogram/utils/domain.js` 在两端与 API 共用校验。基础审核在创建及编辑时拒绝明显的联系方式、地址和 TA 当前私人称呼；这是规则检查，不能保证识别所有可识别信息。用户应在公开预览中核对内容后确认。没有后台人工审核队列。

## API 与持久化

- `POST /v1/cases`：只能引用本人未删除的 `gift_records`；同一礼物同时只能有一个公开案例。
- `GET /v1/cases`：公开案例列表，每页 20 条；支持上述五种筛选及 `offset` 分页。
- `GET /v1/cases/:id`：公开详情；下架后返回 404。
- `POST /v1/cases/:id/helpful`：不能给自己的案例标记；同一账号重复请求只计一次。
- `GET /v1/me/cases`、`PATCH /v1/cases/:id`、`DELETE /v1/cases/:id`：仅作者管理；下架状态保留在作者列表中。

新增的 `003_v02.sql` 可重复执行，不修改旧记录。回退旧代码时保留新表，旧版继续访问私有记录；重新部署 V0.2 后公开案例仍在。若需永久清除公开数据，由账号注销或显式数据处理完成，不通过代码回退清表。
